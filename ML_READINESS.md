# ML readiness and experimentation

## Current production-data gate

The current persistent database did not pass Phase 4A. It has no defensible temporal training/test cohort. Historical aggregates in `legacy_registrations` do not contain attendance outcomes. Late registration/check-in timestamps and stale lifecycle statuses make the nominal historical event unreliable. Eventra therefore must not report current-data model accuracy or train/evaluate a model against these records.

The ML Readiness score is a data-coverage indicator, not a prediction. Its displayed dimensions are completed events, verified outcomes, snapshot coverage, feature completeness, outcome completeness, provenance quality, and consistency. `READY FOR TRAINING` is a preliminary data gate, not a guarantee of sample representativeness, statistical power, or model quality. The current gate also requires at least 30 verified outcomes and 75% cutoff coverage; this is an explicit project policy, not a universal minimum.

## Prediction point contract

Prediction points are 30, 14, 7, and 1 days before the event. For each point, Eventra selects only the latest event snapshot captured at or before its UTC cutoff. Available fields include date/time, category, event/venue capacity and identity, status, confirmed/cancelled registrations, check-ins as of that cutoff, and ticket-type counts. Future registrations/cancellations, post-cutoff check-ins, later edits, and final outcome are unavailable features.

The current snapshot system cannot recreate facts that were never captured. Older events without pre-cutoff snapshots display an unavailable point rather than a reconstructed guess. There are no immutable daily snapshots for periods before this feature was introduced.

## Isolated synthetic experiment

`ml/pipeline.js` produces 160 deterministic simulated events using seed `421042`, ordered at ten-day intervals. Features include registration count/velocity, venue capacity, lead time, expected check-in rate, weekday, month, capacity utilization, and one-hot category. Attendance is generated by a documented linear signal plus seeded noise and bounded by registrations. This is synthetic by construction; it is not sampled from Eventra, a university, or an external event dataset.

The experiment uses a chronological 80/20 train/test split. It compares Eventra's disclosed 72% rule-based planning estimate, a training-mean baseline, and standardized Ridge regression. Feature means/scales are learned from the training partition only. It calculates MAE, RMSE, R², coefficient-based feature importance, and example holdout predictions. Evaluation labels are **Evaluation on synthetic demonstration dataset**. These metrics demonstrate pipeline mechanics only and are not production accuracy.

## Risk labels

Current crowd-risk levels are deterministic thresholds. There are no independent historical risk labels, so Eventra does not train a risk classifier or publish classification metrics. A model trained on threshold-created labels would reproduce those rules rather than validate external risk outcomes.
